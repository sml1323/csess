# Feature Specification: 검색 매치 지점에 앵커되는 프리뷰 (Search-hit-anchored preview)

**Feature Branch**: `001-search-hit-preview`

**Created**: 2026-07-03

**Status**: Draft

**Input**: User description: "지금 검색하면 어디에 그게있는지 안뜨거든. 검색하고, 이제 그 세션 선택하면 ctrl + d u 으로 올리고 내려서 대화 확인할 수 있는데. 이거 딱 그거 grep 한 자리 대화내역 보이게 할순없나"

## 문제 배경 *(context)*

csess는 세션 목록을 **본문(제목+대화 내용)** 대상으로 검색한다. 그래서 어떤 세션은 대화 **중간 어딘가에** 검색어가 있어서 결과에 뜬다. 그런데:

1. 결과 목록은 제목·메타데이터만 보여줄 뿐, **매치가 대화 어디에 있는지, 무엇이 매치됐는지** 알려주지 않는다. "왜 이 세션이 떴지?"를 알 수 없다.
2. 세션을 선택하면 프리뷰가 **항상 맨 위부터** 렌더된다. 검색어 강조도, 매치 지점으로의 이동도 없다. 사용자는 상하 페이징 키로 긴 대화를 **직접 훑어가며** 매치된 부분을 찾아야 한다.

목표: 검색으로 본문이 매치된 세션을 선택하면, **매치된 그 지점의 대화 맥락이 프리뷰에 바로 보이게** 한다("grep 한 자리 대화내역 보이게").

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 매치 지점으로 프리뷰 자동 이동 (Priority: P1)

검색어를 입력해 본문이 매치된 세션이 결과에 뜨고, 그 세션을 선택하면(또는 그 위로 이동하면) 프리뷰가 **맨 위가 아니라 첫 매치가 화면에 보이는 위치**로 자동 스크롤되어 열린다. 매치된 대화 부분이 즉시 눈에 들어온다.

**Why this priority**: 사용자의 핵심 요청("grep 한 자리 대화내역 보이게")이다. 이것 하나만 있어도 "선택 후 손으로 훑기"가 사라져 검색→확인 흐름이 완성되는 MVP다.

**Independent Test**: 대화 아래쪽에만 특정 단어가 있는 긴 세션을 만들고 그 단어로 검색 → 세션 선택 시 수동 스크롤 없이 해당 단어가 있는 대화 구간이 프리뷰에 보이는지 확인.

**Acceptance Scenarios**:

1. **Given** 검색어가 입력돼 있고 그 단어가 대화 후반부 본문에만 있는 세션이 선택됨, **When** 프리뷰가 렌더됨, **Then** 프리뷰는 맨 위가 아니라 첫 매치가 보이는 위치로 스크롤된 상태로 표시된다.
2. **Given** 매치 지점으로 자동 이동된 프리뷰, **When** 사용자가 상하 페이징 키로 스크롤함, **Then** 이후로는 사용자의 수동 스크롤이 우선하며 자동으로 다시 매치 지점으로 끌려가지 않는다.
3. **Given** 검색어를 바꿈, **When** 같은 세션이 그대로 선택돼 있음, **Then** 프리뷰는 새 검색어의 첫 매치 지점으로 다시 이동한다.

---

### User Story 2 - 프리뷰 안에서 매치된 단어 강조 (Priority: P2)

프리뷰 안에 보이는 텍스트 중 검색어와 일치하는 부분이 **시각적으로 강조**되어, 스크롤된 화면에서 눈이 바로 매치 지점에 꽂힌다.

**Why this priority**: 자동 이동(P1)을 보완한다. 매치 지점으로 옮겨줘도 어느 단어인지 강조가 없으면 다시 눈으로 스캔해야 한다. 강조만 단독으로도(수동 스크롤 중이라도) 가치가 있어 독립 검증 가능하다.

**Independent Test**: 화면에 검색어가 보이는 상태에서 그 텍스트가 나머지 본문과 구분되게 강조 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 검색어가 입력됨, **When** 프리뷰에 그 단어를 포함한 줄이 보임, **Then** 해당 단어 부분이 주변 텍스트와 구분되게 강조된다.
2. **Given** 대소문자가 다른 검색어(예: "JWT" vs 본문 "jwt"), **When** 프리뷰가 표시됨, **Then** 대소문자 무관하게 매치되어 강조된다(검색 매칭과 동일 규칙).
3. **Given** 공백으로 구분된 여러 검색어(AND), **When** 프리뷰가 표시됨, **Then** 화면에 보이는 각 검색어가 모두 강조된다.

---

### User Story 3 - 매치 간 이동 (Priority: P3)

한 세션 안에서 검색어가 여러 번 나올 때, 키 하나로 다음/이전 매치로 건너뛴다.

**Why this priority**: MVP 이후의 편의 기능. 매치가 여러 개인 긴 세션에서 유용하지만, 첫 매치 자동 이동(P1)만으로도 핵심 가치는 충족된다.

**Independent Test**: 같은 단어가 3곳에 나오는 세션에서 "다음 매치" 키를 누를 때마다 프리뷰가 다음 매치로 이동하는지 확인.

**Acceptance Scenarios**:

1. **Given** 현재 세션에 검색어가 여러 곳에 있음, **When** "다음 매치" 키를 누름, **Then** 프리뷰가 다음 매치 지점으로 이동한다.
2. **Given** 마지막 매치에 있음, **When** "다음 매치" 키를 누름, **Then** 첫 매치로 순환하거나 그대로 머문다(둘 중 하나로 일관되게 동작).

---

### Edge Cases

- **제목만 매치**: 세션이 제목으로만 매치되고 본문에는 검색어가 없을 때 → 앵커할 본문 지점이 없으므로 프리뷰는 지금처럼 맨 위에서 시작한다(오탐 앵커 금지).
- **매치가 프리뷰에 렌더되지 않는 부분에 있음**: 검색 대상(제목+전체 본문)은 프리뷰보다 넓다. 프리뷰는 도구 호출/사고 과정을 한 줄로 접고 도구 결과는 생략한다. 검색어가 접힌/생략된 부분에만 있으면 프리뷰에 보이는 매치 줄이 없다 → 오류 없이 맨 위(또는 가장 가까운 보이는 지점)로 폴백한다.
- **거대 세션 절단**: 프리뷰는 입력 바이트·출력 줄 상한으로 잘린다. 매치가 상한 뒤에 있으면 앵커할 수 없다 → 폴백한다.
- **빈 검색어**: 검색어가 없으면 앵커·강조 없이 지금 동작(맨 위)을 유지한다.
- **디렉토리/트리 행 등 세션이 아닌 항목 선택**: 프리뷰 앵커 로직은 세션 본문 프리뷰에만 적용되고, 세션이 아닌 프리뷰는 영향받지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 검색어가 활성 상태이고 선택된 세션의 대화 본문에 그 검색어가 존재할 때, 시스템은 프리뷰를 맨 위로 리셋하지 않고 **첫 매치가 프리뷰 영역 안에 보이는 위치**로 스크롤한 채 표시해야 한다(MUST).
- **FR-002**: 자동 이동 시 매치 줄이 화면 최상단 가장자리에 딱 붙지 않도록 **위쪽 맥락 몇 줄**을 함께 보여줘야 한다(MUST). (기본값: Assumptions 참조)
- **FR-003**: 시스템은 프리뷰에 보이는 텍스트 중 검색어와 일치하는 부분을 **시각적으로 강조**해야 한다(MUST).
- **FR-004**: 앵커와 강조는 검색 매칭과 동일하게 **대소문자를 무시**해야 한다(MUST).
- **FR-005**: 공백으로 구분된 여러 검색어(AND)일 때, 시스템은 그중 **어느 검색어든 가장 먼저 나오는 지점**으로 앵커해야 한다(MUST). (Assumptions 참조)
- **FR-006**: 세션이 **제목으로만 매치**되고 본문에는 없을 때, 시스템은 오탐 앵커 대신 맨 위에서 시작해야 한다(MUST).
- **FR-007**: 매치된 텍스트가 본문에는 있으나 **프리뷰에 렌더되지 않는 부분**(접힘/생략/상한 초과)에 있을 때, 시스템은 오류 없이 **정상적으로 폴백**(맨 위 또는 가장 가까운 보이는 지점)해야 한다(MUST).
- **FR-008**: 자동 앵커 이후에도 사용자는 기존 상하 페이징으로 자유롭게 스크롤할 수 있어야 하며, 한 번 수동 스크롤하면 그 선택이 유지되는 동안 **수동 스크롤이 자동 앵커보다 우선**해야 한다(MUST).
- **FR-009**: 선택된 세션이 그대로일 때 **검색어가 바뀌면** 시스템은 앵커를 다시 계산해야 한다(MUST).
- **FR-010**: 검색어가 **비어 있으면** 시스템은 앵커·강조 없이 현재 동작(맨 위)을 유지해야 한다(MUST).
- **FR-011** *(P3)*: 시스템은 현재 세션 안에서 **다음/이전 매치로 이동**하는 키 조작을 제공해야 한다(MUST, P3 범위).

### Key Entities *(include if feature involves data)*

- **검색어(Query terms)**: 공백으로 분리된 substring 항목들(AND). 대소문자 무시. 앵커·강조의 기준.
- **대화 프리뷰(Conversation preview)**: 세션에서 렌더되어 화면에 보이는 대화 줄의 나열. 검색 대상 본문보다 좁다(도구/사고 접힘, 도구 결과 생략).
- **매치 위치(Match location)**: 프리뷰 줄 나열 안에서 검색어가 처음/그다음으로 나타나는 지점. 앵커가 이동할 목표.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 본문으로 매치된 세션을 선택했을 때, 매치가 프리뷰 렌더 범위 안에 있는 경우 **수동 스크롤 없이** 관련 대화 구간을 볼 수 있다(해당 케이스의 ≥95%).
- **SC-002**: 세션이 "왜 매치됐는지"를 확인하는 데 걸리는 시간이 상하 훑기(수 초~수십 초)에서 **선택 즉시(약 2초 이내)**로 줄어든다(본문 매치 기준).
- **SC-003**: 검색어가 화면에 보일 때 강조 표시가 100% 나타나 매치 텍스트가 주변과 구분된다.
- **SC-004**: 엣지 케이스(제목만 매치, 렌더 안 되는 부분 매치, 절단된 세션, 빈 검색어)에서 오류·크래시 0건.
- **SC-005**: 앵커·강조가 프리뷰 응답성에 **체감 지연을 더하지 않는다**(선택·스크롤 시 키 입력 대비 눈에 띄는 랙 없음, 기존 "스크롤 idle" 특성 유지).

## Assumptions

- 앵커 대상은 렌더된 대화에서 **어느 검색어든 가장 먼저 나오는 지점(첫 매치)**이다. 여러 검색어가 서로 가까이 있는지(proximity)는 고려하지 않는다.
- 가독성을 위해 매치 줄 **위쪽에 소수의 맥락 줄**을 함께 보여준다(정확한 줄 수는 구현 세부, 폴리시로 조정 가능).
- 검색 대상(제목+전체 본문)은 렌더 프리뷰보다 넓다. 접힘(도구/사고)·생략(도구 결과)·상한 초과로 프리뷰에 없는 매치는 폴백한다(v1에서 접힌 블록을 펼쳐 매치를 드러내지는 않는다).
- 프리뷰의 입력 바이트·출력 줄 상한은 유지된다. 상한 밖 매치는 앵커되지 않는다.
- 대상 범위: Claude·Codex 세션 모두, TUI 한정.
- v1 범위 밖: 퍼지 매치 강조(현재 검색은 exact substring AND), 정규식, 세션 간 매치 순회.

## Dependencies

- 기존 본문 검색(제목+본문 substring AND, 대소문자 무시)과 인프로세스 프리뷰 렌더에 의존한다. 이 기능은 그 위에 매치 위치 계산·앵커·강조를 얹는다.
